# v1.8.6 — Angular Material printer selection field follow-up (23/10/2026)

## Owner field defect v1.8.5
- On in tem chẵn, WMS shows **CHỌN MÁY IN** with already-selected printer `21-1129-D29 (Online)`. The application reports **Không đọc được danh sách máy in WMS (OK)**; options have not expanded.
- Explicit required route when opening IN TEM CHẴN: `https://wms-supra.winmart.vn/sft3/app/saleorder/list`. This is already configured in `WmsBrowser.cs` and remains unchanged.
- The previous recorder ZIP (private; not committed) includes input[role=combobox] manual pointerdown, focus and click, a `mat-autocomplete` overlay of `mat-option` choices, then changed printer => `Xác nhận`, unchanged printer => `Đóng`. Screenshots show the dialog and current value, not an actual print.
- Root cause supported by source: `EXPAND` used focus/click and fired `input` **without resetting a populated search query**. Angular autocomplete may keep the panel filtered to no options. Prior mocked test opened options on `focus` unconditionally and thus failed to reproduce the issue. A second risk: `ShowDialog` steals WebView2 focus and closes the autocomplete before a selected option can be clicked.

## Corrections
1. On opening the printer input, focus and clear **only the displayed Angular autocomplete search query**, dispatch the `input` event so Angular refreshes the full set. Do not alter stored WMS printer settings until the operator selects a real option.
2. Preserve the original printer text from the initial WMS dialog. Require explicit selection from the scanned real options. Always select a real WMS `mat-option` after the picker returns (including unchanged printer), then read back its value. Use **Confirm** only for a different saved printer; use **Close** for the unchanged printer.
3. After the native WinForms picker closes, reopen the Angular list because the overlay can close when WebView2 loses focus. Do not click disabled Confirm.
4. Provide bounded failure diagnostics (dialog/input/expanded/option counts, no printer names or WMS auth data in logs).
5. Change the test fixture: populated query produces **no list**, and the list appears **only after clearing query + input event**. Also simulate blur from the native picker and re-open; retain changed/unchanged validation for list and packing routes.

## Safety / verification
- Fail closed: SO remains locked until the chosen saved printer is read back in WMS. No accidental auto-print or retry.
- In-tem-lẻ packing business workflow unchanged.
- Gate 1: Windows CI compile + JavaScript and DOM regression + GUI smoke.
- Gate 2: Owner confirms on actual WMS Office network, including list route, manual SSO, complete printer options, different printer Confirm, unchanged printer Close, no double modal. CI is not evidence of physical printing.
